# E2E 録画起点の計画生成（代替 Step1）

対象機能: **$1**
録画JSON / 補足コンテキスト: $ARGUMENTS

**`e2e-record` skill** を起動し、ChromeDevTools Recorder の録画JSON（`$2`）を種に、対象機能 `$1` の **遷移マップ付き plan** を起こす。これは `e2e-map`（通常 Step1）の**代替 Step1**であり、出力の体裁は e2e-map と揃える（後段 `e2e-spec`（Step2）へそのまま渡せる）。

- **冒頭で既存 `e2e/index.md`（横断スナップショット）を読む**（無ければ `e2e/plans/*.md` をスキャン）。既検証の経路は重複作成せず、未検証を優先する。
- **録画は「正確な happy path の種＝ヒント」であって正解ではない。** エフェメラルなセレクタ（UUID id・座標依存・深い nth-of-type）は【要修復】として明示し、後段のライブ探索へ送る。
- **価値フロー vs 後始末は構造だけでは切れない。** 推測ラベルを提示して人間に確定させる。ミス入力（打ち間違い→取り消し）も人間判断へ回す。
- **意図確認は一括で投げる**（機能名・中心価値・成功の定義WHAT・後始末ラベル・ミス入力の採否・再生時 `E2E_AUTH_MODE`・実行ロール名(slug)）。推測で決め打ちしない。
- 成果物: `e2e/plans/<slug>.md`（遷移マップ節＋録画固有3節: 5観点係留メモ / 要修復セレクタ / 未確定オラクルHOW）。詳細は skill 本文に従う。
- **plan.md を出したら止まる。** ライブ探索・要修復解決・オラクルHOW確定・Playwrightコード生成には進まない（後段の責務）。**コードは書かない。**

> 生成した plan は `/e2e-planner:e2e-plan` の Step2（`e2e-spec`）以降へ手動で引き継げる（録画モードのオーケストレーター自動配線は未実装）。
